**When:** Use `exec` to dispatch an exact `sulla meta/<tool>` command. Discover current tools with `sulla meta/browse_tools '{"category":"meta"}'` before an unfamiliar call.

**Tools:**
- `sulla meta/upsert_conversation_keywords '{"terms":"[]","thread_id":"<thread_id>"}'`: Observer-only database writer for salient terms from the completed conversation turn. Canonicalizes and upserts terms by (term, thread_id), bumping hit_count and last_seen on repeats. Required: terms, thread_id.
- `sulla meta/search_conversation_keywords '{}'`: Read-only search for the Conversation Reader over the conversation_keywords index. Pass term (or query) for exact canonical-term match, falling back to pg_trgm fuzzy match, falling back to ILIKE over conversation_history title/summary/last_summary; or pass thread_id to list every indexed keyword for that thread. Deliberately includes conversations hidden from the primary UI (subconscious/worker channels) — that is the point of this tool. Required: none.
- `sulla meta/add_observational_memory '{"content":"<content>"}'`: Use this tool to store the observations you make into long-term memory. Required: content.
- `sulla meta/search_conversation_logs '{}'`: Read-only search over ~/sulla/logs/ for the Conversation Reader. Pass thread_id to resolve that conversation\'s specific log file(s) (channel-scoped .log plus the conv_<id>.jsonl event stream); omit it to scan all thread-scoped log files within a recency window (since / days). Add keyword to filter to matching content lines instead of whole-file listings/previews. Excludes global non-thread-scoped infra logs (chat.log, dispatcher.log, index.log, etc). Required: none.
- `sulla meta/exec '{}'`: Run any shell command inside a fully isolated sandboxed Linux VM with root access. This is ALSO how you invoke every `sulla <category>/<tool>` CLI command surfaced by browse_tools — pass the full `sulla ...` command string as the `command` arg (e.g. command: "sulla github/create_issue \'{\\"title\\":\\"bug\\"}\'"). Safe to install packages, compile code, delete files, or run any system command. Required: none.
- `sulla meta/exechost '{}'`: LAST RESORT host shell — runs a command on the HOST macOS machine, NOT the Sulla VM. Default to regular exec (VM sandbox) for everyday work; home files are already mounted into the VM. Use exechost ONLY when the parent host MUST be used (host-only binaries/GUI apps, host Docker Desktop, tools unavailable in the VM, or explicit user request). Uses the user\'s login shell (/bin/zsh or /bin/bash) so PATH includes Homebrew/nvm/rbenv. Silent output, no Terminal window. Requires "Allow access to the host machine" in Preferences → Application → Administrative Access. Prefer this over AppleScript→Terminal when host execution is truly required. Required: none.
- `sulla meta/remove_observational_memory '{"id":"<id>"}'`: Archive (soft-delete) a specific observational memory by its ID. The record is never hard-deleted — it is marked archived=true so the history is always recoverable. Required: id.
- `sulla meta/search_observations '{"query":"<query>"}'`: Search active observational memories by meaning with the ranked recall engine (keyword + embedding search + learned ranker), so paraphrases match. Returns compact rows (id, priority, timestamp, relevance score, content), best first. include_archived falls back to any-word keyword matching. Use this before adding a new observation to check for existing similar ones. Required: query.
- `sulla meta/list_observations '{}'`: List active observational memories sorted by priority (critical/high first) then recency. Optionally filter by priority level. Required: none.
- `sulla meta/add_identity_observation '{"level":"1","content":"<content>"}'`: Store a focused identity observation into the domain-keyed identity_observations table (human / business / world / agent / environment / projects / skills — mirrors ~/sulla/identity/). Levels are CERTAINTY: 3 = stated fact (subject directly told us), 2 = derived fact (established from conversation evidence), 1 = conclusion (reasoned from L3/L2 facts — personality, style, habits). Pass an existing id to update in place; otherwise a substantially similar active row in the same domain is updated instead of duplicated. Required: level, content.
- `sulla meta/remove_identity_observation '{"id":"<id>"}'`: Archive (soft-delete) an identity observation by its ID. The record is never hard-deleted — it is marked archived=true so the history is always recoverable. Required: id.
- `sulla meta/search_identity_observations '{"query":"<query>"}'`: Search active identity observations within one domain (human / business / world / agent / environment / projects / skills) by meaning with the ranked recall engine (keyword + embedding search + learned ranker), so paraphrases match. Rows include a relevance score, best first. include_archived falls back to any-word keyword matching. Use this before adding a new identity observation to check for existing similar ones. Required: query.
- `sulla meta/list_identity_observations '{}'`: List active identity observations for one domain, most certain first (L3 stated → L2 derived → L1 concluded) then most recent. Optionally filter by level and/or category. Required: none.
- `sulla meta/update_identity_section '{"id":"<id>","content":"<content>"}'`: Write the consolidated identity profile for a domain into its system-prompt section (e.g. the "user" section injected into every system prompt). Overwrites the section content and marks it customized so the boot seeder never clobbers it. Used by the nightly "dreaming" consolidation routines; DB-only, no filesystem. Required: id, content.
- `sulla meta/ask_user_question '{"questions":"[]","items":"<items>","properties":"<properties>","question":"<question>","header":"<header>","multiSelect":"true","options":"[]","label":"<label>","description":"<description>"}'`: Pause and ask the user one or more multiple-choice questions, then BLOCK until they answer in the chat (or the timeout elapses — default 5 min). Renders an interactive card with selectable options; the user may also type a free-form answer. Returns the selected option(s) per question. Use whenever the next step depends on a decision only the user can make — picking between approaches, confirming an assumption, supplying a missing detail, or getting a yes/no go-ahead (offer Approve / Deny options). Required: questions, items, properties, question, header, multiSelect, options, items, properties, label, description.
- `sulla meta/file_search '{"query":"<query>"}'`: Fast full-text keyword search (BM25-ranked) across any directory PLUS the bundled sulla-docs (agent + tool reference) by default. Faster than find or grep for multi-word queries — use this as your default search tool. Matches file contents and filenames. Small directories are live-scanned (always fresh); large ones use an incremental on-disk index built automatically, with coverage reported when partial. Pass includeSullaDocs:false to skip the sulla-docs second pass. Required: query.
- `sulla meta/read_file '{"path":"<path>"}'`: Read the contents of a file with optional line range. Returns line-numbered content and the total line count. Can also list directory contents. Required: path.
- `sulla meta/write_file '{"path":"<path>","content":"<content>"}'`: Write or overwrite file contents. Creates parent directories if needed. Restricted to the home directory. Required: path, content.
- `sulla meta/recall_index_lookup '{}'`: Check the Redis citation index for previously-researched digests BEFORE re-reading files or re-searching directories. Pass a topic and/or a list of file paths. Returns trusted digests for files verified unchanged (cheap content-hash check), drops stale entries automatically, and lists which paths/topics need fresh research. Required: none.
- `sulla meta/recall_index_store '{"items":"<items>","properties":"<properties>","path":"<path>","digest":"<digest>"}'`: Persist freshly-researched citation digests into the Redis citation index so future recall passes can reuse them without re-reading source files. Store one entry per file you read (path + the digest you produced), and optionally a topic with citation strings. Entries are verified against file content hashes and expire after 24h unless re-hit. Required: items, properties, path, digest.
- `sulla meta/recall_conversations '{"action":"<action>"}'`: Search and read the on-disk conversation logs (~/sulla/logs/conv_*.jsonl) — the training-formatted JSONL transcripts of every past user-facing conversation (subconscious agents are never logged here). Unlike search_conversations (which matches DB titles/summaries), this searches the actual message CONTENT and returns transcripts. action:"search" finds past conversations by keyword and returns each hit\'s id, date, title, and a matching snippet; action:"read" renders one conversation\'s full transcript by id. Use this to recall what was actually said/decided in earlier conversations. Required: action.
- `sulla meta/browse_tools '{}'`: Discover available sulla CLI tools by category or keyword. Returns ready-to-run `sulla <category>/<tool>` commands with descriptions and parameter JSON. IMPORTANT: the commands it returns are NOT directly callable tools — you invoke each one by passing the full command string to the `exec` tool (e.g. exec({command: "sulla docker/ps \'{}\'"})). NEVER call execute_workflow for any command listed here — execute_workflow is only for named Sulla workflows. Call this before attempting any sulla CLI invocation you are unsure about. Required: none.

**Do:**
1. Discover the category when names or parameters may have changed.
2. Run the command through `exec`, passing one JSON object with required parameters.
3. Treat returned IDs, cursors, and SHAs as inputs to the next call; verify destructive or outward-facing results.

**Don't:**
- Don't call `execute_workflow` for CLI tools; dispatch tools through `sulla meta/exec`/`exec`.
- Don't use `exechost` unless the host is physically required.
- Don't invent workflow slugs or tool names.
