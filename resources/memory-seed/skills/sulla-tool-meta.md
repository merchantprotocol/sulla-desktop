**When:** Use `exec` to dispatch an exact `sulla meta/<tool>` command. Discover current tools with `sulla meta/browse_tools '{"category":"meta"}'` before an unfamiliar call.

**Tools:**

<!-- tools:generated:start -->
- `sulla meta/ask_user_question '{"questions":[]}'`: Pause and ask the user one or more multiple-choice questions, then BLOCK until they answer in the chat (or the timeout elapses — default 5 min). Renders an interactive card with selectable options; the user may also type a free-form answer. Returns the selected option(s) per question. Use whenever the next step depends on a decision only the user can make — picking between approaches, confirming an assumption, supplying a missing detail, or getting a yes/no go-ahead (offer Approve / Deny options). Required: questions. Optional: timeoutMs.
- `sulla meta/browse_tools '{}'`: Discover available sulla CLI tools by category or keyword. Returns ready-to-run `sulla <category>/<tool>` commands with descriptions and parameter JSON. IMPORTANT: the commands it returns are NOT directly callable tools — you invoke each one by passing the full command string to the `exec` tool (e.g. exec({command: "sulla docker/ps '{}'"})). NEVER call execute_workflow for any command listed here — execute_workflow is only for named Sulla workflows. Call this before attempting any sulla CLI invocation you are unsure about. Required: none. Optional: category, query.
- `sulla meta/dry_run_workflow '{}'`: Walk a workflow statically — parse YAML, traverse from triggers, report execution order and any orphans or runtime-ambiguous branches. Does NOT execute any node (no side effects). Use to verify routing before committing to a live run. Required: none. Optional: slug, filePath.
- `sulla meta/exec '{}'`: Run any shell command inside a fully isolated sandboxed Linux VM with root access. This is ALSO how you invoke every `sulla <category>/<tool>` CLI command surfaced by browse_tools — pass the full `sulla ...` command string as the `command` arg (e.g. command: "sulla github/create_issue '{\"title\":\"bug\"}'"). Safe to install packages, compile code, delete files, or run any system command. Required: none. Optional: command, cmd, cwd, timeout, stdin.
- `sulla meta/exechost '{}'`: LAST RESORT host shell — runs a command on the HOST macOS machine, NOT the Sulla VM. Default to regular exec (VM sandbox) for everyday work; home files are already mounted into the VM. Use exechost ONLY when the parent host MUST be used (host-only binaries/GUI apps, host Docker Desktop, tools unavailable in the VM, or explicit user request). Uses the user's login shell (/bin/zsh or /bin/bash) so PATH includes Homebrew/nvm/rbenv. Silent output, no Terminal window. Requires "Allow access to the host machine" in Preferences → Application → Administrative Access. Prefer this over AppleScript→Terminal when host execution is truly required. Required: none. Optional: command, cmd, cwd, timeout, stdin, foreground.
- `sulla meta/execute_workflow '{"workflowId":"<workflowId>"}'`: Execute a pre-registered workflow by its EXACT slug. Only call this when the slug appears verbatim in the "Available workflows" section of your system prompt — never guess a slug from the user request (e.g. do NOT invent slugs like "browser-tab-open" or "ask-date-time" unless they are explicitly listed). If no workflow matches the user intent, use exec({ command: "sulla <category>/<tool> '...'" }) instead — NOT this tool. This tool CANNOT open browser tabs, run shell commands, or call sulla CLI tools. Required: workflowId. Optional: message, resume.
- `sulla meta/file_search '{"query":"<query>"}'`: Fast full-text keyword search (BM25-ranked) across any directory PLUS the bundled memory seed (agent + tool reference) by default. Faster than find or grep for multi-word queries — use this as your default search tool. Matches file contents and filenames. Small directories are live-scanned (always fresh); large ones use an incremental on-disk index built automatically, with coverage reported when partial. Pass includeSullaKnowledge:false to skip the bundled memory seed second pass. Required: query. Optional: dirPath, limit, reindex, includeSullaKnowledge, includeSullaDocs.
- `sulla meta/pause_workflow '{"executionId":"<executionId>"}'`: Pause a running workflow without releasing it. Cooperative — PlaybookController checks a Redis flag at each frontier tick and halts frontier advance. In-flight sub-agent work is NOT cancelled. Resume with resume_workflow. Required: executionId. Optional: reason.
- `sulla meta/read_file '{"path":"<path>"}'`: Read the contents of a file with optional line range. Returns line-numbered content and the total line count. Can also list directory contents. Required: path. Optional: startLine, endLine.
- `sulla meta/restart_from_checkpoint '{}'`: Restart a workflow execution from a specific node checkpoint. Use workflowId alone to list recent executions, executionId alone to list checkpoints, or executionId + nodeId to restart from that node. Required: none. Optional: executionId, nodeId, workflowId.
- `sulla meta/resume_workflow '{"executionId":"<executionId>"}'`: Resume a workflow paused with pause_workflow by clearing its pause flag. The orchestrator resumes frontier advance on its next tick. Required: executionId. Optional: none.
- `sulla meta/spawn_agent '{}'`: The one way to delegate. Launch one or more child agents, each with a return contract. visibility "hidden" (default) runs the child in the background; visibility "tab" opens it as a live chat tab the human can join (use for leads that run their own team or keep a visible Playbook). Every child shows in your sub-agent rail and your <subagent_directory> block, finishes with agents/return_result, and its result wakes you. Supports parallel execution and async (fire-and-forget) mode for hidden children. Required: none. Optional: tasks, parallel, async.
- `sulla meta/stop_workflow '{"executionId":"<executionId>"}'`: Request a running workflow to stop. Cooperative — writes a Redis flag the PlaybookController checks at each frontier tick, so the running orchestrator honors it on its next step. If the orchestrator is blocked on a long-running sub-agent or LLM call, the abort takes effect when that call returns. For immediate hard-kill, restart Sulla Desktop. Required: executionId. Optional: reason.
- `sulla meta/validate_sulla_workflow '{}'`: Validate a Sulla workflow YAML file for structural correctness before it goes live. Checks top-level schema, node types, subtype/category mapping, required config fields, edge format, trigger presence, and reachability. Use this EVERY time you create or edit a Sulla workflow YAML. Required: none. Optional: filePath, yaml.

**Do:**
1. Discover an unfamiliar command with `sulla meta/browse_tools '{"query":"<need>"}'`.
2. Run the exact returned CLI string through `exec`.
3. Use `sulla meta/exec '{"command":"<shell command>"}'` for VM shell work and `sulla meta/ask_user_question '{"questions":[]}'` when a user decision is required.
4. Use `sulla meta/dry_run_workflow '{"slug":"<known slug>"}'` before a live run; use `sulla meta/execute_workflow '{"workflowId":"<exact listed slug>"}'` only for a named workflow.
5. Use `sulla meta/pause_workflow '{"executionId":"<id>"}'` and `sulla meta/resume_workflow '{"executionId":"<id>"}'` to control an existing run.

**Don't:**
- Don't read "destructive operations are safe" as covering the human's data: it applies only to scratch inside the VM. Deleting the human's files or other durable data still waits for their tap.
- Don't call `execute_workflow` for a catalog CLI tool; it accepts named workflow slugs only.
- Don't use `exechost` for routine VM work or put secrets in command arguments.
