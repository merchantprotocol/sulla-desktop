# Spyglass

Create a factual competitor profile from public URLs and compare later snapshots. Default to a quick scan; use a deep profile only when requested.

## When to use
Use for “profile this competitor”, “compare these competitors”, or “what changed on their pricing page?”

## Instructions
1. Ask for competitor URLs, quick or deep scan, dimensions, and whether to compare against the human’s product when those are not already supplied.
2. Use Sulla’s browser read tools on public pages only. Open the homepage, pricing, product/features, and relevant public proof pages. Record the URL and retrieval date for every fact.
3. Quick scan covers homepage and pricing; deep scan may add docs, changelog, public reviews, technology signals, and content. Never bypass authentication, robots controls, paywalls, or rate limits.
4. Keep facts separate from interpretation. Quote or summarize visible claims, normalize pricing units, and label hypotheses. Never claim traffic, SEO, reviews, or features without a source.
5. Save one profile per competitor and a comparison summary in an existing Files folder only when requested. Include positioning, pricing, messaging, proof, gaps, opportunities, threats, and raw URLs.
6. On an update, check pricing first, then re-read the same pages and add a Change Log. Compare snapshots and notify only with a draft report; do not contact competitors or publish anything.
